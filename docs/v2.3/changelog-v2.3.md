# 变更日志 - v2.3

## 需求背景

当前游戏中的关卡参数仍然散落在主流程逻辑中，至少存在以下问题：
- 关卡的目标分、步数等核心参数不够集中，后续扩关和调平衡成本高
- 小丑牌槽位目前只有全局解锁概念，缺少“本关允许使用几个槽位”的关卡限制
- 通关奖励缺少明确的“新卡牌解锁”配置与提示，玩家难以感知成长反馈

v2.3 的目标是将**关卡规则配置化**，并把“每关挑战限制”和“通关奖励反馈”统一纳入关卡配置体系，方便后续持续扩展内容。

---

## 功能变更点

### 1. 抽离关卡配置（核心改动）

需要新增独立的关卡配置结构，用于统一管理每一关的核心参数。

#### 关卡配置至少包含
- `targetScore`：本关目标分
- `moves`：本关总步数
- `maxSlots`：本关允许使用的最大卡牌槽位数
- `unlockJokers`：本关通关后可解锁的小丑牌列表

#### 配置形式要求
- 关卡配置应从主流程逻辑中抽离，不再把目标分、步数直接硬编码在流程函数内
- 配置应集中放在一个明确位置，便于后续继续新增关卡
- 当前版本至少需要覆盖现有已实现的关卡流程

### 2. 关卡目标分、步数改为读取配置

#### 具体要求
- 开局初始化关卡时，不再使用散落的默认值
- 当前进入的关卡，应从关卡配置中读取：
  - 目标分
  - 总步数
- UI 中展示的目标分、剩余步数，也必须与当前关卡配置保持一致

#### 目标
- 后续新增新关卡时，只改配置，不改主流程逻辑

### 3. 关卡可配置最大卡牌槽位

#### 新规则
- 玩家全局已解锁的槽位数，仍然保留
- 但每一关实际可使用的槽位数，还要受到该关 `maxSlots` 限制
- 本关可用槽位数 = `min(玩家已解锁槽位数, 当前关卡 maxSlots)`

#### 具体表现
- 进入关卡前的选牌界面，只展示本关允许使用的槽位数量
- 如果玩家已全局解锁 3 个槽位，但某关 `maxSlots = 1`，则本关只能装备 1 张牌进入挑战
- 超出本关限制的槽位内容，不参与本局结算与触发

### 4. 通关后解锁新小丑牌

#### 配置规则
- 每个关卡可以在 `unlockJokers` 中配置若干张通关奖励牌
- 当玩家首次通关该关时，解锁这些小丑牌
- 已经解锁过的奖励，不应重复解锁

#### 数据效果
- 新解锁的小丑牌应进入玩家可持有/可获得的卡牌集合
- 如果当前项目中“小丑牌是否已解锁”尚未独立建模，则本版本需要补充最小可用的数据记录方式
- 解锁结果应可持续保留，不应因为单局重开而丢失

### 5. 通关后增加“新卡牌解锁”提示

#### 展示时机
- 玩家达成本关目标分并通关后，在结算/通关反馈中提示本关解锁内容

#### 展示内容
- 明确展示：
  - “解锁了哪些新小丑牌”
  - 卡牌名称
  - 卡牌图标 / 类型（如当前已有现成视觉资源则复用）
- 如果该关没有配置新解锁内容，则不显示该模块
- 如果该关奖励之前已拿过，本次通关不重复弹“新解锁”提示

### 6. 关卡推进逻辑需适配配置化设计

#### 要求
- 当前关卡编号与关卡配置正确对应
- 进入下一关时，读取下一关配置
- 若后续关卡已存在但未配置，应有安全兜底，避免出现读取报错

## 实现建议（供程序员参考）

### 关卡配置建议结构
可使用如下结构之一：
- `LEVEL_CONFIGS = [{...}, {...}]`
- 或 `LEVEL_CONFIGS = { 1: {...}, 2: {...} }`

示例字段：

```js
{
  id: 1,
  targetScore: 300,
  moves: 8,
  maxSlots: 0,
  unlockJokers: ['voidEye']
}
```

### 推荐拆分点
- `config.js`：新增或集中管理关卡配置
- `index.html`：
  - 初始化关卡时读取配置
  - 选牌界面按 `maxSlots` 限制展示
  - 通关时发放关卡解锁奖励
  - 通关弹窗增加“新卡牌解锁”提示区

## 不变的部分

- 小丑牌槽位的全局购买价格不变（10 / 30 / 90）
- 槽位触发概率仍为 30%
- 单方块最多附着 3 张小丑牌的规则不变
- 计分公式不变：`(基础分 + 基础分加成) × (基础倍率 + 倍率加成)`
- 基础倍率仍按“被移动方块是否位于交叉点”判定
- 小丑牌手动附着与自动附着机制继续保留
